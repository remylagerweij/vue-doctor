# Vue Doctor 2.0 — Full Analysis & Change Plan

- **Date:** 2026-10-02
- **Repo:** `remylagerweij/vue-doctor` @ `5fc96f1` (package `@remylagerweij/vue-doctor` v1.1.2)
- **Method:** a code read plus four specialist reviews: security, architecture/performance, dependencies, and product/DX/CI/agents. Three rounds of owner decisions followed.
- **Scope:** analysis only. No code was changed.

---

## 0. Executive summary

Vue Doctor has a good shape: three analyzers run in parallel and produce a 0–100 score. In practice several parts are silently broken, so it can't be trusted as a CI gate yet:

| # | Finding | Impact |
|---|---|---|
| 1 | **Template linting (eslint-plugin-vue) has never produced a result.** It calls ESLint 10 with removed eslintrc flags, ignores the exit code, and still shows "✓ succeeded". | All 19 template rules, including `vue/no-v-html`, do nothing |
| 2 | **The scan rewrites user source files on disk** to strip `eslint-disable` comments, and restores them only in `finally`. | Ctrl-C or a crash leaves the user's repo modified. It also races with HMR and editors |
| 3 | **Shell injection.** `npx eslint` runs with `shell: true`, and in `--diff` mode git file names are passed in unescaped. | A PR containing a file named `$(…).vue` gets RCE on the CI runner |
| 4 | **The CLI always exits 0.** `--json` is not valid JSON, because spinners and the header go to stdout. | It can't gate CI, and agents can't parse the output |
| 5 | **Security coverage is mostly illusory.** `no-eval` is never enabled. `no-v-html` is a placeholder that matches the literal `"<script>alert"`. The secrets rule skips `apiKey`. | A project with obvious leaks still scores 90+ |
| 6 | **Rule metadata is spread over 4 files that have drifted.** Five rules are registered but disabled. 11 rules show up as category "Other". | Wrong reports and wrong docs |
| 7 | **The Action** runs a second full scan just to read the score, always uses `@latest`, has no PR comments, and can't fail. | Not usable as a PR check |
| 8 | **The build breaks on Windows** and deletes `dist/`. `tsc --noEmit` fails because of a knip internal import. 17 audit advisories (1 critical, in vitest). | Contributor friction and supply-chain hygiene |

**Plan:** go straight to **2.0.0**, a breaking redesign, on Node 22 + 24. 2.0 includes:

- a pure core API, with the CLI, Action and MCP server as thin layers on top
- a single rule registry
- an exit-code and baseline gate on new issues only
- SARIF, JSON and Markdown formatters
- a configurable PR feedback system with AI-agent fix prompts
- `ci install` and `agents install` commands
- an MCP server
- four new security guardrail packs
- a VitePress docs site

## 2. Current state

### 2.1 Architecture (as-is)

```
cli.ts (commander) ─► selectProjects (monorepo prompt / --project)
  └─ for each project (sequential) ─► [--diff] getDiffInfo (git ×4-5)
       └─ scan.ts
           discoverProject  (package.json, configs, workspaces, git ls-files)
           loadConfig       (vue-doctor.config.json | package.json#vueDoctor)
           ┌──────────── Promise.all ────────────────────────────────────┐
           │ runOxlint   : neutralize eslint-disable ON DISK → tmp       │
           │               .oxlintrc → spawn oxlint (JS plugin) → parse  │
           │ runEslintVue: tmp eslintrc → `npx eslint` (shell:true) ✗    │
           │ runKnip     : in-process knip internal `main()`             │
           └─────────────────────────────────────────────────────────────┘
           combineDiagnostics → filterDiagnostics → calculateScore
           output: json | score | html | GH summary | console  (exit 0)
index.ts diagnose(): a diverged copy of the pipeline (no eslint-vue, sequential)
```

Rule metadata currently lives in four places:

1. `plugin/index.ts` (registration)
2. `oxlint-config.ts` (severity / enablement)
3. `run-oxlint.ts:20-78` (category map)
4. `run-oxlint.ts:80-185` (help text)

## 5. Security

### 5.1 Security of the tool itself

| ID | Sev | Finding | Fix |
|---|---|---|---|
| T1 | High | Shell injection via diff file names (D3) | Run ESLint in-process; `--` separators |
| T2 | High (by design) | **Scanning executes the target repo's code.** knip loads `vite.config`, `nuxt.config` and `vitest.config` via jiti, and `npx eslint` resolves the project's ESLint binary | Document it in the threat model. Refuse to run when `GITHUB_EVENT_NAME=pull_request_target` unless `--i-know-this-runs-pr-code` is passed. Use the bundled ESLint only |
| T3 | Medium | Mutates user files (D2) | Delete the mechanism |
| T4 | Med/Low | Predictable temp paths (`tmpdir/vue-doctor-*-${pid}.json`) are vulnerable to a symlink race | Use `fs.mkdtempSync` and write with `flag:'wx'`, `mode:0o600`. Better: pass config in memory (in-process ESLint; oxlint `-c` pointing at a mkdtemp file) |
| T5 | Medium | `action.yml` runs `npx @latest` twice and isn't SHA-pinned | Pin the CLI to the action's version; scan once |
| T6 | Low | Unquoted `$INPUT_PROJECT`; output injection through a newline in `directory` | Quote it; validate inputs; use a heredoc delimiter for `$GITHUB_OUTPUT` |
| T7 | Low | `--diff <branch>` can be read as a git option | Reject values starting with `-`; use `--end-of-options` |
| T8 | Low | The nvm installer runs `execSync` via bash with environment-derived paths | Remove auto-install; just print guidance |
| T9 | Low | The GitHub summary and PR comments interpolate rule messages (which contain user identifiers) without escaping | Escape Markdown and HTML in all Markdown formatters |
| T10 | Low | Release job: unpinned `npm@latest` with `id-token: write` | Pin npm and SHA-pin actions |
| — | OK | `load-config.ts` only uses `JSON.parse`. oxlint and git are spawned with argv arrays | Keep that property when TS config support arrives: load TS config only from the project root, and never in `pull_request_target` |

**New:** add a `SECURITY.md` with a disclosure policy and a threat model. The threat model states that scanning untrusted code is equivalent to running it.

### 5.2 Existing security rules: gaps

| Rule | Problem |
|---|---|
| `no-secrets-in-client-code` (`security.ts:14-39`) | The suffix allow-list includes `key`, `id`, `url` and `config`, so `apiKey = "…"` is skipped. SCREAMING_CASE is split into single letters. Only `VariableDeclarator` is checked; properties, assignments and templates are not. `sk-` pattern fails on `sk-proj-`/`sk-ant-`. `auth` matches `author`. Also runs on `server/**` |

| `nuxt-no-process-env-in-client` | Fires in `server/` and `nuxt.config.ts`, where `process.env` is legitimate. Misses `import.meta.env` |

### 5.3 New guardrail packs (all four approved)

- **AST**: the oxlint JS plugin (script and TS)

## 6. Performance

Prioritized, with estimated impact:

| # | Change | Where | Impact |
|---|---|---|---|
| P1 | Run ESLint in-process instead of `npx eslint` | `run-eslint-vue.ts` | **−1.5 to 2.5 s per scan** (npx alone costs ~2.6 s on Windows). Template checks start working |
| P2 | Delete `neutralizeDisableDirectives` | `run-oxlint.ts:332` | Removes a full read of every js/ts/vue file plus writes. Seconds saved on large repos |
| P3 | Lazy-load knip, eslint, `@clack/prompts` and the formatters | `cli.ts`, runners | **About −1 s startup.** `--version` is 1.2–1.8 s today because knip alone takes ~1.1 s to import |
| P4 | Run knip **once** at the monorepo root and split results per workspace; scan projects with limited concurrency | `run-knip.ts:129-140`, `cli.ts` | knip runs once instead of N times. knip is the slowest tool on real repos |
| P5 | Content-hash cache: `sha1(file) + configHash + toolVersions → diagnostics` in `node_modules/.cache/vue-doctor`; only changed files go to oxlint and ESLint. knip is cached on a hash of the lockfile and tree | new `core/cache.ts` | **5–10× faster warm re-runs.** Agent fix loops benefit most. CI persists the cache via `actions/cache` |
| P6 | Run diff-mode oxlint batches in parallel (`Promise.all`, bounded) | `run-oxlint.ts:348` | Linear speed-up for large diffs |
| P7 | Precompile ignore globs once (picomatch); memoize `findMonorepoRoot` and package.json reads; skip the `git ls-files` count in json/score mode | `filter-diagnostics.ts:19`, `match-glob-pattern.ts:8`, `discover-project.ts:61` | Small |

Avoids materialising oxlint's lazy AST |
| P9 | Stop patching the global `console` (`silenced()`) while analyzers run in parallel | `run-knip.ts:58` | Correctness for API users |
| P10 | Bounded output buffers, `--max-diagnostics`, and stream JSONL output for huge repos | runners, formatters | Memory safety |
| P11 | Report per-pass timings (`--timings`, and always in JSON) | core | Makes later optimisation measurable |

## 7. Rule quality

### 7.1 Rules with many false positives (fix, test, demote until fixed)

| Rule | False positive today | Fix |
|---|---|---|
| `no-missing-await-next-tick` (`reactivity.ts:154`) | Flags every `nextTick`, including awaited ones | Only flag when the call isn't awaited, returned or `.then`-ed |
| `no-async-setup-without-suspense` (`vue-specific.ts:16`) | Flags every `await` in a `.vue` file | Only top-level `await` in `<script setup>` / `setup()` |
| `no-this-in-setup` (`correctness.ts:58`) | Flags Options API `this` | Only inside `setup()` / `<script setup>` |
| `no-array-index-as-key` | Flags any `.map((x,i)=>…)` | Needs template context (move to TPL) |
| `nuxt-no-window-in-ssr` (`nuxt.ts:128`) | Flags `window.*` inside `onMounted` and `import.meta.client` guards | Skip guarded scopes |
| `js-set-map-lookups` | Flags `string.includes` | Only when the receiver is an array |
| `require-emits-declaration` | Flags every `$emit` | Only when `defineEmits`/`emits` is missing |

### 7.2 Testing standard (per rule)

- At least 3 `valid` and 3 `invalid` cases in the RuleTester style. Each rule file sits next to its test.
- A fixture **snapshot test** for each category, stored as JSON keyed by ruleId and count. This is the oxlint and knip upgrade guard.
- **"Analyzer is alive" tests**: each pass must produce more than 0 findings on basic-vue. This would have caught D1 and the knip-6 trial failure.
- Tests for `get-diff-files`, `filter-diagnostics`, `load-config`, `select-projects`, formatters, CLI exit codes, and JSON validity.
- Delete the stray `tests/debug-test.ts` and the dead code listed in the architecture review: `installNodeViaNvm`, `setSelectBanner`, `REACTIVE_APIS`, `isComposableCall` and others.

```jsonc
  "score": { "value": 84, "label": "Great", "base": 86, "delta": -2,

             "capped": { "by": "security/no-hardcoded-secret", "max": 50 } },
  "summary": { "errors": 2, "warnings": 9, "new": 3, "fixed": 1, "suppressed": 4 },
  "findings": [{
    "ruleId": "vue-doctor/security/no-unsafe-html-sink",
    "severity": "error", "category": "security", "confidence": "high",
    "cwe": ["CWE-79"], "owasp": "A03:2021",
    "file": "src/components/Post.vue", "line": 12, "column": 5, "endLine": 12, "endColumn": 31,
    "message": "…", "help": "…",

```

- Ordering is deterministic (file, line, column, ruleId), paths are POSIX-relative, and `--no-timestamp` is available.
- `--format jsonl` streams one finding per line. The final line is the summary.

### 8.2 Formats (`--format a,b --output dir|file`)

| Format | Purpose |
|---|---|
| `text` (default) | Human-readable terminal output |
| `json` / `jsonl` | Agents, the MCP server, and integrations |
| `sarif` | GitHub code scanning. `security-severity` is set from rule metadata |
| `github` | `::error file=,line=,col=,title=::` annotations |
| `markdown` | PR comment, step summary, and agent prompts. HTML/Markdown is escaped (T9) |
| `html` | Kept but upgraded: light and dark themes, filters, code frames, `file:line` links, docs links. Written to `--output`, not into the project root |

### 8.3 Score

The existing unique-rule penalty is kept, versioned and documented. Two things are added:

- **Category sub-scores**, computed with the same formula per category.
- A **security cap**: any `error` + `confidence:high` security finding caps the score at 50. A critical secret caps it at 30.

Each output also shows "fixing X gains +N".

### 8.4 Logging

| Behaviour | Detail |
|---|---|
| Streams | Reports go to stdout. Everything else (banner, spinners, warnings) goes to stderr |
| Levels | `--quiet`, the default, `--verbose`, and `--debug` (equivalent to `DEBUG=vue-doctor:*`). Debug output shows the resolved config, tool versions and argv, file counts, ignored files, cache hits, and timings |
| Colour and TTY | `NO_COLOR`, `FORCE_COLOR` and `--no-color`. Spinners are off outside a TTY and when `CI` is set |
| Failed passes | Shown prominently. `--strict` turns a skipped pass into exit 3 |

### 8.5 Configuration

```ts
// vue-doctor.config.ts
import { defineConfig } from "@remylagerweij/vue-doctor";
export default defineConfig({
  extends: ["vue-doctor/recommended"],       // or "strict", "security"
  rules: { "vue-doctor/performance/no-deep-watch": "off",
           "vue-doctor/security/no-hardcoded-secret": ["error", { entropy: true }] },
  ignore: { files: ["src/legacy/**"], rules: [] },
  gate: { failOn: "error", scope: "new", minScore: null },
  audit: { enabled: false },
  baseline: ".vue-doctor-baseline.json",
  pr: { modes: ["summary", "findings"], grouping: "rule-per-file", maxComments: 30, agentPrompt: true },
});
```

- Config is loaded with c12/jiti, from the project root only.
- JSON is also supported, with `$schema` pointing at a published JSON Schema.
- Unknown keys produce errors, which fixes D10.

### 8.6 Baseline & history

| Command | What it does |
|---|---|
| `vue-doctor baseline` | Writes `.vue-doctor-baseline.json` with fingerprints that survive line shifts |
| `--baseline <file>` | Marks matching findings as `status: baseline` |
| `vue-doctor history` | Appends to `.vue-doctor/history.jsonl`. Optional; the Action can show a trend on push builds |

## 9. CI solution (GitHub Actions)

### 9.1 Architecture

```
            ┌──────────── action.yml (composite) ─────────────┐
 PR / push ─►│ setup-node (SHA) → cache (npm + .cache/vue-doctor)│
            │ npx @remylagerweij/vue-doctor@${action_version}   │
            │      ci run  --scope changed --format json,sarif  │
            │      ci report (PR feedback via GitHub REST)      │
            │ [optional] upload-sarif · upload-artifact (html)  │
            └───────────────────────────────────────────────────┘
```

- **All logic lives in the CLI** (`vue-doctor ci run` / `ci report`). The composite action is thin glue, so GitLab can be added later with only a template.
- **One scan.** The score, outputs and comments are all derived from the same JSON. This removes the second `@latest` run.
- **Version pinning.** The action resolves the CLI version from its own tag (`${{ github.action_path }}/package.json` or a release-time constant), so `@v2` of the action never runs v3 of the CLI.

### 9.2 Inputs and outputs

| Input | Default | Notes |
|---|---|---|
| `version` | the action's own version | Override if needed |
| `node-version` | `24` | |
| `directory`, `project` | `.`, — | |
| `scope` | `changed` on PRs, `full` on push | `changed` \| `lines` \| `full` |
| `fail-on` | `error` | `none` \| `error` \| `warning` |
| `gate` | `new` | `new` \| `all` |
| `min-score` | — | Optional extra gate |
| `feedback` | `summary,findings` | Any of `summary`, `annotations`, `findings`, `none` |
| `grouping` | `rule-per-file` | `finding` \| `rule-per-file` \| `rule` |
| `max-comments` | `30` | Overflow goes to the summary |
| `agent-prompt` | `true` | Adds the copy-paste AI block (§9.4) |
| `sarif` | `false` | Needs `security-events: write` |
| `baseline` | — | Path to the baseline file |
| `audit` | `false` | OSV, network |
| `report` | `false` | Uploads the HTML report as an artifact |
| `github-token` | `${{ github.token }}` | |

**Outputs:** `score`, `base-score`, `score-delta`, `errors`, `warnings`, `new-issues`, `fixed-issues`, `sarif-path`, `report-path`, `json-path`.

### 9.3 Feedback modes (configurable; default `summary,findings`)

| Mode | Behaviour |
|---|---|
| `summary` | A **sticky comment** identified by `<!-- vue-doctor:summary -->`, edited in place and never duplicated. Contains the score, the delta against base, new and fixed counts, category sub-scores, the top rules with docs links, a collapsed full list, and an "all issues" AI prompt block |
| `annotations` | Check-run annotations / `::error` lines on changed lines. These need no PR write permission, so they work on fork PRs |
| `findings` | PR review comments anchored to added lines. `grouping` sets one comment per finding, per rule-per-file, or per rule. Each comment carries a `<!-- vue-doctor:finding:<fingerprint> -->` marker, so reruns **update, resolve or delete** stale comments instead of stacking new ones. Capped by `max-comments` |
| `none` | Gate and step summary only |

The step summary (`$GITHUB_STEP_SUMMARY`) is always written. A commit status is always set, for example "Vue Doctor 84 (−2) · 3 new issues".

### 9.4 AI agent prompt block (on every finding comment and in the summary)

````markdown
<details>
<summary>🤖 Fix with an AI agent</summary>

```text
You are fixing a Vue Doctor finding in this repository.
Rule: vue-doctor/security/no-unsafe-html-sink (error, CWE-79)
File: src/components/Post.vue:12-12
Problem: v-html renders unsanitized user content (post.body).
Guidance: Sanitize with DOMPurify before binding, or render as text. See https://…/rules/security/no-unsafe-html-sink
Constraints: keep behaviour identical; don't disable the rule; add/adjust a test if one exists.
Verify: run `npx @remylagerweij/vue-doctor . --scope changed --format json` and confirm the finding is gone.
```
</details>
````

- GitHub shows a copy button on fenced code blocks.
- Prompts are generated from rule metadata (`agentGuidance` field), so they stay consistent with the docs.
- No secret values are ever included, because matched secrets are masked.

### 9.5 Fork PRs and permissions

- **Trigger:** `pull_request` only. Never use `pull_request_target` with a checkout of PR code, because scanning executes repo config (T2).
- **Fork PRs:** the job still scans and gates, writes the step summary and annotations, and uploads `vue-doctor.json` as an artifact. The optional second workflow, `vue-doctor-comment.yml` on `workflow_run`, downloads that artifact and posts the comments with a write token, **without checking out PR code**.
- **Permissions:**

  | Permission | When |
  |---|---|
  | `contents: read` | Always |
  | `pull-requests: write` | Always |
  | `checks: write` | Always |
  | `statuses: write` | Always |
  | `security-events: write` | Only when `sarif: true` |

- **Base score:** push-to-default-branch runs save `vue-doctor.json` to `actions/cache` keyed by commit SHA. PR runs restore it by merge-base SHA. On a cache miss, the base is scanned in a `git worktree` (needs `fetch-depth: 0`; the action warns when the checkout is shallow).
- **Concurrency:** `group: vue-doctor-${{ github.ref }}`, `cancel-in-progress: true`.

### 9.6 One-command install

```bash
npx @remylagerweij/vue-doctor@latest ci install
```

- Detects the package manager, monorepo layout, default branch and existing workflows.
- Writes `.github/workflows/vue-doctor.yml`, plus `vue-doctor-comment.yml` when `--fork-comments` is passed. Minimal permissions; action pinned to `@v2`.
- Shows a diff before writing. Does nothing if nothing would change. Refuses to overwrite without `--force`.
- Flags: `--yes`, `--fail-on`, `--feedback summary,findings,annotations`, `--grouping`, `--sarif`, `--audit`, `--fork-comments`.
- Related commands:

  | Command | Purpose |
  |---|---|
  | `ci config` | Prints the YAML to stdout |
  | `ci upgrade` | Re-renders the workflow, keeping user inputs |
  | `vue-doctor init` | Wizard: writes the config, then offers CI install and agent install |

Generated workflow (abridged):

```yaml
name: Vue Doctor
on:
  pull_request: { types: [opened, synchronize, reopened, ready_for_review] }
  push: { branches: [main] }
permissions: { contents: read, pull-requests: write, checks: write, statuses: write }
concurrency: { group: vue-doctor-${{ github.ref }}, cancel-in-progress: true }
jobs:
  vue-doctor:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@<sha> # v7
        with: { fetch-depth: 0 }
      - uses: remylagerweij/vue-doctor@v2
        with:
          fail-on: error

          grouping: rule-per-file
          agent-prompt: true
```

## 15. Risks & open items

| Risk | Mitigation |
|---|---|
| oxlint's JS plugin API is alpha and can break any release | Exact pin, snapshot guard, and an abstraction layer between rule code and oxlint |
| oxlint still can't parse `<template>` | Template rules run on the ESLint template engine (`engine: "eslint-template"` in the registry). Re-check whether oxlint gains native Vue SFC support |
| Taint-style rules (SSRF, open redirect, validation) produce false positives | Single-function taint only; ship at `warning`/medium confidence; promote using real-world data |
| Scanning executes repo code through knip and config loading (T2) | Document it; block in `pull_request_target`; fork-safe two-stage workflow |
| The 2.0 rule-ID rename breaks user configs | Alias map + deprecation warnings + migration guide |
| knip 6's API shape differs from 5 | Dedicated PR with a count-parity check against knip 5's result on the fixture |
| GitHub API rate limits on large PRs | Comment cap; batch review creation; update instead of re-create |
