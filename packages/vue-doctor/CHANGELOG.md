# @remylagerweij/vue-doctor

## 2.0.2

### Patch Changes

- eb5830a: `ci run` keeps PR comments separate per scanned directory. When a workflow scans several monorepo projects in parallel (one matrix job each), every job used to overwrite the same sticky summary, so only the last project to finish was visible, and each job deleted the other jobs' review comments as stale. The sticky summary marker now carries the scanned directory (`<!-- vue-doctor:summary:apps/web -->`) and the summary title names it; review comments carry a `<!-- vue-doctor:scope:… -->` marker and a scan only updates or removes its own. A scan of the repository root keeps the existing markers, so single-project repositories see no change.

## 2.0.1

### Patch Changes

- 16b0de2: `ci run` now anchors PR review comments and annotations at repository-relative paths. When the scanned directory was not the repository root (a monorepo app such as `apps/web`, or a workspace project), review comments used project-relative paths and GitHub rejected every one with `422 path could not be resolved`. `--feedback annotations` in `ci run` now goes through the same escaped formatter as `--format github`, so a finding message can no longer inject a workflow command.

## 2.0.0

📦 **NPM Package**: [`@remylagerweij/vue-doctor`](https://www.npmjs.com/package/@remylagerweij/vue-doctor) (`npm i -D @remylagerweij/vue-doctor` / `npx @remylagerweij/vue-doctor@latest`)

### Major Changes

- 4dc773e: Vue Doctor 2.0. See the migration guide for every breaking change.
  
  - Requires Node.js `^22.12.0 || >=24.0.0` (Node 20 is end-of-life).
  - `import "@remylagerweij/vue-doctor"` is now the side-effect-free programmatic API (`diagnose()`, types). `./api` remains as an alias. The `diagnose()` result shape changed: `{ project, diagnostics, score, label, skipped, timings }`, and it now includes template (eslint-plugin-vue) findings like the CLI.
  - Status output (banner, spinners, hints, warnings) now goes to stderr; stdout carries only the report. `--json` across several workspace projects prints a single `{ "projects": [...] }` document.
  - Exit codes are now a stable contract: `0` ok, `1` gate breached, `2` usage/config error, no Vue project or cancelled prompt, `3` analyzer failure with `--strict`. New gating flags: `--fail-on <none|error|warning>` (default `none`), `--gate <new|all>`, `--min-score <0-100>`, `--strict`. Unknown flags and invalid values now exit `2`.
  - Vue Doctor no longer tries to install or switch Node versions via nvm. Lint runs on the current Node when it satisfies `^22.12.0 || >=24.0.0`; otherwise the lint pass is skipped with the detected version and install guidance. Node 23 is not supported.
  - Template checks (eslint-plugin-vue) now actually run: they previously spawned `npx eslint` with an eslintrc config that ESLint 10 no longer supports, silently returned nothing, and used a shell. They now run in-process with Vue Doctor's own bundled ESLint (flat config; your project's ESLint and config are never loaded) and honor the root `.gitignore`. Added `vue/no-template-target-blank` (Security). Expect new findings and a lower score on projects that were previously never checked.
  - `--diff` now works in monorepo sub-projects (project-relative paths), includes untracked files, rejects invalid refs, warns on stderr before falling back to a full scan, and skips the project when no source files changed.
  - Vue Doctor never modifies project files anymore: the on-disk `eslint-disable` neutralisation (which could leave files modified after Ctrl-C or a crash) is gone. `eslint-disable` / `oxlint-disable` comments no longer hide findings (files containing them are linted from a temp copy; the template check runs ESLint with `--no-inline-config`). Use the new `// vue-doctor-disable-next-line [rules]`, `vue-doctor-disable-line`, `vue-doctor-disable` / `vue-doctor-enable` and `vue-doctor-disable-file` comments (also as HTML comments in `.vue` templates, with an optional `-- reason`). `diagnose()` results gain `suppressed: { count, byRule }` and `foreignDirectives`.
  - Configuration is validated (exit `2` with the offending keys) instead of being silently ignored, and `vue-doctor.config.ts/.mts/.js/.mjs` are supported via `defineConfig()`. New keys: `extends` presets, per-rule `rules` severities, `gate`, `audit`, `baseline`, `pr`. `lint`, `deadCode`, `verbose` and `diff` are now honoured. `ignore.paths` was never read; use `ignore.files`. A JSON Schema ships at `@remylagerweij/vue-doctor/schema.json`.
  - New `vue-doctor baseline` command and `--baseline <file>` flag (or config `baseline`): findings get a stable `fingerprint` (rule + file + normalized source line) and `status: "baseline" | "new"`, so `--gate new` fails only on findings introduced after the baseline.
  - Dead-code analysis moved to Knip 6 (oxc-based; the `typescript` runtime dependency is gone, Vue Doctor no longer pulls it into your install). Dead code is now also reported for projects without an installed `node_modules` and no longer depends on where the project lives on disk (previously it silently returned nothing without `node_modules`).
  - New `--quiet`, `--debug` (or `DEBUG=vue-doctor:*`), `--timings` and `--no-color` flags; the JSON report includes per-analyzer `timings`. When an analyzer cannot run, a prominent warning now lists it with the reason in every output mode (also `--json` and `--score`).
  - Re-runs are much faster: findings are cached per file content hash in `node_modules/.cache/vue-doctor` (or the user cache directory for projects without `node_modules`; `VUE_DOCTOR_CACHE_DIR` overrides), and only changed files are re-analyzed. The cache invalidates on tool, Vue Doctor or analyzer-config changes; `--no-cache` or config `cache: false` disables it.
  - Five rules that were registered but never ran are now on: `no-eval` (Security, error), `pinia-no-destructure`, `pinia-no-watch-store`, `router-no-string-push` and `router-no-async-guard-without-next` (Ecosystem, warning). Their false positives were fixed first: `pinia-no-destructure` ignores destructured actions, `pinia-no-watch-store` no longer matches names like `restore`, `router-no-string-push` only reports paths built by interpolation or concatenation (not static paths such as `/login`), and `router-no-async-guard-without-next` now reports an async guard that declares `next` and never calls it (returning nothing is valid in Vue Router 4). `no-eval` also catches `window.eval()` and `globalThis.eval()`. Expect new findings.
  - Severity policy: a rule defaults to `error` only when it is a high-confidence Security rule or a Correctness rule that reliably indicates a bug; everything else is a `warning`. Now `error`: `no-eval`, `no-this-in-setup` and the `eslint-plugin-vue` correctness checks (`require-v-for-key`, `valid-v-slot`, `valid-v-bind`, `valid-v-on`, `valid-v-model`, `no-dupe-keys`, `no-duplicate-attributes`, `return-in-computed-property`). Demoted to `warning`: `no-secrets-in-client-code` (medium confidence), `no-async-setup-without-suspense`, `no-nested-component-definition`, `no-fetch-in-watch`, `no-mutation-in-computed`, `no-reactive-replace`, `no-watch-for-computed`, `no-global-css-variable-animation`, `no-layout-property-animation`, `nuxt-async-client-component`, `nuxt-no-process-env-in-client`, `nuxt-no-window-in-ssr`, `nuxt-require-server-route-error-handling`, `vue/no-use-v-if-with-v-for`, `vue/no-mutating-props`, `vue/no-computed-properties-in-data`, `vue/no-side-effects-in-computed-properties`, `vue/no-async-in-computed-properties` and `vue/no-ref-as-operand`. A unique rule now costs 0.75 score points as a warning instead of 1.5 as an error, so scores rise on projects that triggered the demoted rules, and `--fail-on error` no longer fails on them (use `--fail-on warning` or the `rules` config to keep that). Override any rule with the `rules` config. The rules page lists every rule with its default severity (generated by `npm run rules:table`).
  - Fewer false positives in seven rules: `no-missing-await-nextTick` (only bare discarded calls), `no-async-setup-without-suspense` and `no-this-in-setup` (only the real setup scope, not nested functions or Options API methods), `no-array-index-as-key` (only when the index is used as a `key`), `nuxt-no-window-in-ssr` (skips `import.meta.client`/`typeof window` guards, client-only hooks and `.client` files), `js-set-map-lookups` (only array receivers) and `require-emits-declaration` (only when `defineEmits`/`emits` is missing).
  - Interactive prompts and progress now use `@clack/prompts` (replacing `prompts` and `ora`). Progress shows one spinner naming the running analyzers, then a ✔/✖ line per analyzer; without a TTY or in CI it prints plain lines, and `--quiet` prints nothing. Cancelling a prompt exits `2`.
  - **Breaking:** the JSON output is now the versioned `vue-doctor/report@2` document (JSON Schema at `@remylagerweij/vue-doctor/report-schema.json`). It always has the `projects[]` shape, also for a single project (previously a flat object, and `{ "projects": [...] }` only for several). Findings are now `findings[]` with `ruleId`, `file` (POSIX, project-relative), `confidence`, `docsUrl`, `codeFrame` and `agentPrompt`; `diagnostics`, `rule`, `skippedChecks`, `elapsed` and `timestamp` are gone (use `findings`, `ruleId`, `skipped`, `timings.total` and `generatedAt`). New `--format <text|json|jsonl>` (`--json` stays as an alias), `--output <file>` and `--no-timestamp`.
  - **Breaking:** rule IDs are now namespaced by category: `vue-doctor/<category>/<rule>` (for example `vue-doctor/security/no-eval`, `vue-doctor/bundle-size/no-moment`). This is the ID in the JSON report (`ruleId`, `docsUrl`, `suppressed.byRule`), in baselines and in the generated rules table; template rules stay `vue/<rule>` and dead code `knip/<type>`. The 1.x IDs (`no-eval`, `vue-doctor/no-eval`) still work in `rules`, `ignore.rules` and `vue-doctor-disable*` comments, but print one deprecation warning per distinct ID per run naming the replacement. `rules`/`ignore.rules` also accept groups such as `vue-doctor/security/*`, and an ID that matches no rule now warns instead of silently doing nothing. A bare `vue-doctor/<rule>` suppression no longer also silences the `vue/<rule>` template rule of the same name; list both.
  - **Breaking:** the score is now versioned (`scoreVersion: 2`) and security findings cap it: a high-confidence security error (for example `no-eval`) caps the overall score at 50, and a critical secret (`no-secrets-in-client-code` at `error` severity) at 30, so scores can drop. The unique-rule penalty itself is unchanged. New: per-category sub-scores and "Fixing X gains +N" impact hints in the text output (top 3) and in the JSON report (`projects[].score` now also has `rawScore`, `cap`, `categories` and `impact`; the report root has `scoreVersion`). `--score` still prints a single integer and `--min-score`/`gate.minScore` compare against the capped score. See the new Scoring guide.
  - New `--format sarif` writes a SARIF 2.1.0 log for GitHub code scanning (`github/codeql-action/upload-sarif`): one run per project, rules with CWE tags and `security-severity` from rule metadata, stable `partialFingerprints`, baseline state, and deterministic truncation at GitHub's 25,000-results limit. See the new "GitHub code scanning" guide.
  - Monorepos: knip now runs once for the whole monorepo (findings are split per project by file path) and projects are scanned concurrently (at most half the CPUs, max 4), with output printed per project in a fixed order. A monorepo root that is itself a Vue/Nuxt app (e.g. Nuxt app with only `docs` in `pnpm-workspace.yaml`) is now scanned as a project next to its workspaces, without the files of those workspaces; previously only the workspaces were scanned. `projects[].root` in the JSON report is now relative to the scanned directory (`.` for the project at it) instead of the working directory.
  - New `--format github` prints GitHub Actions workflow commands (`::error file=...,line=...,title=<rule id>::message`), so findings appear as annotations on the changed lines of a pull request, also on fork PRs where SARIF upload is not permitted. Low-confidence warnings are notices, values are escaped so a finding can never inject another workflow command, and a final notice says how many findings exist because GitHub shows at most 10 annotations per level per step. See the new "GitHub annotations" guide.
  - Agent prompts are richer and safe to paste: `findings[].agentPrompt` is now a plain-text prompt with rule, location range, problem, the rule's guidance, constraints and a verify command (`npx @remylagerweij/vue-doctor <root> --diff --format json`). New `projects[].ruleGroups[]` carries one prompt per rule with several findings (locations capped at 10, then "and N more"). Token-like values are masked, and secret findings never include code frames in prompts.
  - New `--format markdown`: a summary (score with cap note, category sub-scores, biggest improvements, counts, baseline, skipped analyzers; per project for monorepos) followed by findings grouped by rule, capped deterministically and kept under GitHub's 65,536-character comment limit. Messages, paths and project names are escaped (HTML, Markdown, `@mentions`, `#123` references, autolinks), links are only built from trusted docs URLs, and Security findings never include source. `--github-summary` now writes this Markdown to `GITHUB_STEP_SUMMARY` (previously unescaped, and only for the text format).
  - **Breaking:** the secrets rule is reworked and split in two. `no-secrets-in-client-code` is replaced by `vue-doctor/security/no-hardcoded-secret` (`error`, high confidence, `critical`: credentials in the formats of OpenAI, Anthropic, Google, GitHub, GitLab, Slack, Stripe live keys, Supabase `service_role` (anon keys do not fire), AWS access key IDs, SendGrid, npm, Hugging Face and PEM private keys, derived from gitleaks) and `vue-doctor/security/no-secret-named-literal` (`warning`: a secret-named variable, property, assignment, class field or default parameter such as `apiKey`, `API_SECRET`, `x-api-key` or `password` holding a random-looking literal, plus provider keys committed in `server/`, `*.config.*` and test files). Both scan every string, object property, assignment, template literal and default parameter, split names correctly in camelCase, snake_case, SCREAMING_CASE and kebab-case (`apiKey` and `author` are no longer misjudged), and ignore placeholders, env lookups and public keys. The old ID still works in `rules`, `ignore.rules` and suppression comments with a deprecation warning and selects both new rules. A leaked provider key now caps the score at 30 and fails `--fail-on error`. Messages name the provider and the variable, never the value, and findings of secret rules no longer carry a `codeFrame` in the JSON report.
  - **Breaking:** the placeholder rule `vue-doctor/security/no-v-html` (it only matched the literal `<script>alert`) and `vue/no-v-html` (which flagged every `v-html`, even sanitised) are replaced by one real rule, `vue-doctor/security/no-unsafe-html-sink` (CWE-79, OWASP A03, warning, medium confidence: whether the value is attacker-controlled is not knowable statically). It reports unsanitised HTML in templates (`v-html`, `:innerHTML.prop`, `v-bind="{ innerHTML }"`) and in scripts (`el.innerHTML = x`, `outerHTML`, `insertAdjacentHTML`, `setHTMLUnsafe`, `createContextualFragment`, `document.write`, `h(tag, { innerHTML })`, Vue 2 `domProps: { innerHTML }`, JSX `innerHTML`/`v-html`/`dangerouslySetInnerHTML`). String literals, templates without interpolation, direct sanitizer calls (`DOMPurify.sanitize(x)`, `sanitizeHtml(x)`, `$sanitize(x)`, `filterXSS(x)`) and, in scripts, `const` bindings initialised with one are not reported; a variable is never trusted because of its name. The old IDs (`no-v-html`, `vue-doctor/no-v-html`, `vue-doctor/security/no-v-html`, `vue/no-v-html`) keep working in `rules`, `ignore.rules` and suppression comments as deprecated aliases of the new rule. Expect new findings for `innerHTML` and similar sinks.
  - **Breaking:** the HTML report is rebuilt as `--format html` (`vue-doctor . --format html --output report.html`): one self-contained file (no external requests) built from the report@2 model with light/dark themes, every finding (paginated) with filters (severity, category, rule, project, search, new only), code frames with line numbers, copyable `file:line`, docs links and collapsible AI fix prompts; escaped, with a strict Content-Security-Policy, and no code frames for Security findings. `--report` no longer writes `vue-doctor-report.html` into the scanned project: it is deprecated, prints a warning and writes the report to a private temporary directory (the path is printed). See the new "HTML report" guide.
  - New secret-exposure rules, plus a new analyzer for them. "Project checks" (`engine: "fs"`, `defineFsRule`) run rules over project files with `git ls-files` (directory walk outside git), appear as `project` in progress, `timings` and the cache, and skip with `projectChecks: false` in `diagnose()`. New warnings: `vue-doctor/security/no-committed-env` (tracked `.env` files: always `*.local`, otherwise only with secret-looking values), `vue-doctor/security/no-secret-in-public-env-file` (`VITE_*`/`NUXT_PUBLIC_*`/`PUBLIC_*` variables named like secrets in `.env*`), `vue-doctor/security/no-secret-in-public-env` (the same names read via `import.meta.env`, `process.env` or `useRuntimeConfig().public`) and `vue-doctor/nuxt/no-secret-in-public-runtime-config` (secrets in `runtimeConfig.public` or `app.config`). Findings never contain values. `nuxt-no-process-env-in-client` no longer reports `process.env.NODE_ENV`, test files or `server/` sub-directories like `tasks`. `vue-doctor-disable` comments also work with `#` in `.env` files. The JSON report's `skipped[].tool` can now be `vue-doctor`, and the cache format changed (one-time cold run).
  - New rule `vue-doctor/security/no-llm-sdk-in-client` (warning, high confidence, CWE-522/CWE-200, OWASP A05): LLM provider SDKs imported in client code (`openai`, `@anthropic-ai/sdk`, `@google/generative-ai`, `@google/genai`, `@ai-sdk/<provider>`, `groq-sdk`, `@mistralai/mistralai`, `cohere-ai`, ...), `dangerouslyAllowBrowser: true`, and `fetch`/`$fetch`/`axios`/`ky` calls to provider API hosts all ship the API key to every visitor. Server code (`server/`, `*.server.*`, config files), tests, type-only imports, `@ai-sdk/vue` and requests to your own routes are not reported.
  - New XSS, URL and code-sink rules (Security, all `warning`, so they never fail `--fail-on error` on their own): `vue-doctor/security/no-javascript-url` (CWE-79, high confidence: literal `javascript:` URLs such as `href="javascript:void(0)"`, `` `javascript:${x}` ``, `"javascript:" + x`, in templates and scripts; blocklist comparisons like `url.startsWith("javascript:")` are not reported), `vue-doctor/security/no-user-controlled-url` (CWE-79/601, medium: route query/params, stripped `location.hash`/`search`, `window.name` and `URLSearchParams` values reaching `:href`/`:src`/`:action`/`:formaction`, `location.href`/`assign`/`replace`, `window.open`, `el.href`/`src`; silenced by a validator call, `new URL(x)` or a `startsWith("/")` check, and not reported behind a literal prefix such as `` `/search?q=${q}` ``), `vue-doctor/security/no-dynamic-code` (CWE-95, medium: `new Function(x)`, string `setTimeout`/`setInterval`, Vue runtime `compile(x)` and non-literal `template:` options; `eval()` stays under `no-eval`, so nothing is reported twice), `vue-doctor/security/postmessage-origin-check` (CWE-346, medium: `message` listeners that read `event.data` without `event.origin`/`event.source`, and `postMessage(sensitiveData, "*")`) and `vue-doctor/security/no-token-in-web-storage` (CWE-922, medium: tokens, JWTs and session ids written to `localStorage`/`sessionStorage`, `useLocalStorage`/`useStorage` and Pinia `persist`; CSRF and design tokens are ignored). `vue/no-template-target-blank` was already enabled. Expect new findings.
  - New opt-in dependency audit: `--audit` (or `audit.enabled` in the config) reads `package-lock.json`/`npm-shrinkwrap.json`, `pnpm-lock.yaml`, `yarn.lock` (classic and Berry) or the text `bun.lock` (the monorepo root lockfile for workspaces), asks OSV.dev which installed versions have known vulnerabilities and reports each on the lockfile as `vue-doctor/supply-chain/vulnerable-dependency` (new Supply Chain category, `warning`, CWE-1395, OWASP A06:2021; GHSA/CVE IDs, highest severity and fixed version in the message). It sends only package names and versions, caches answers for 24 hours in the cache directory, is skipped with a reason (`audit` in `skipped`, tool `osv.dev`) when `--offline`/`VUE_DOCTOR_OFFLINE=1` is set or OSV cannot be reached, and makes no network call at all unless enabled. The `vue-doctor/security` preset also keeps Supply Chain findings. New `audit` analyzer in `diagnose()` (`audit`, `auditFetch` options). See the new "Dependency audit" guide.
  - New "Supply Chain" category (own sub-score) with three project-check rules, plus a public-folder rule. `vue-doctor/supply-chain/lockfile-integrity` (warning) reports a project with dependencies and no lockfile (looked up in the monorepo root too), lockfiles of several package managers side by side, and lockfile packages resolved from a host other than the configured registry (`registry.npmjs.org`; `.npmrc` / `.yarnrc.yml` registries are respected); `vue-doctor/supply-chain/no-remote-dependency-spec` reports git, `http://` and tarball dependency specs (git specs pinned to a full commit hash are fine); `vue-doctor/supply-chain/no-dependency-install-scripts` (low confidence) lists direct dependencies with install scripts. `vue-doctor/nuxt/no-sensitive-public-file` reports files in `public/` (and Nuxt `static/`) that are deployed publicly: `.env*`, private keys, database dumps, source maps, backups, logs, `.DS_Store` and `.git/`, including untracked and git-ignored ones. Expect new findings, notably for projects that do not commit a lockfile.
